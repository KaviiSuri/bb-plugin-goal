# Domain docs

This repository has one domain context.

Before working on domain behavior, read `CONTEXT.md` at the repository root and relevant records under `docs/adr/`. If either path does not exist, continue. The domain-modeling workflow creates files only when a term or decision is settled.

Use glossary terms in task titles, test names, code, and documentation. If planned work conflicts with an ADR, state the conflict before changing the decision.

The layout is:

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```
